## Product Goal

Capture the current working application behavior as the v0.2.0 baseline. Where behavior differs from v0.1.0, the current implementation is the intended v0.2.0 design unless explicitly changed by a later requirements document.

## Current Baseline

### Runtime and Security

- The app is an Electron desktop application with a renderer, preload, main process, and process-isolated local agent worker.
- Electron windows use `contextIsolation: true`, `sandbox: true`, and `nodeIntegration: false`.
- Renderer code remains UI-only. Storage, configuration, validation, and agent orchestration are owned by main-process code.
- Renderer capabilities are exposed through the typed `window.reviewAssistant` preload API over allowlisted IPC channels.

### Configuration

- App-level configuration is loaded from `config/.env` relative to the current working directory.
- Backend selection precedence is:
  1. `AZURE_STORAGE_ACCOUNT_CONNSTRING`
  2. `AZURE_STORAGE_ACCOUNT_NAME`
  3. `LOCAL_PATH`
- If no supported backend key exists, project browsing is blocked and the UI shows a configuration error.
- Variable expansion is not performed.
- Secret values, including `AZURE_STORAGE_ACCOUNT_CONNSTRING`, are redacted in logs.
- Project-level `config/.env` files may override non-backend settings.
- Project-level `config/.env` files must not override backend selection keys (`AZURE_STORAGE_ACCOUNT_CONNSTRING`, `AZURE_STORAGE_ACCOUNT_NAME`, or `LOCAL_PATH`) in the local backend.

### Project and Storage Model

- A project is the review isolation boundary.
- Local projects are subdirectories under `LOCAL_PATH`.
- Azure projects are Blob containers.
- New projects can be created from the UI. Project names must be valid Azure container-style names: 3-63 lowercase letters, numbers, and hyphens.
- New projects are initialized with a default `config/schema.json`.
- Opening a project requires `config/schema.json`; missing schema files fail clearly and do not silently fall back.
- Record discovery includes project-root `.json` files.
- Record identifiers and project identifiers must not be empty, traverse paths, or contain path separators.

### Schema Validation and Rendering

- Records are read-only.
- Records are validated with Ajv 2020 plus JSON Schema formats.
- Validation errors are shown in the details panel.
- Object, array, primitive, enum, description, and `allOf`-merged schemas render as structured read-only fields.
- Complex JSON Schema constructs such as `$ref`, `oneOf`, `anyOf`, conditionals, `not`, `dependentSchemas`, and `patternProperties` are validated and displayed as deterministic read-only raw JSON fallback nodes.
- Array object items are collapsed by default and use their first field value as the summary identifier when available.

### User Interface

- The core workspace has three adjustable columns: record list, record details, and local agent chat.
- The header includes a current-project selector and a create-project action.
- The record list can be refreshed for the selected project.
- The footer shows the generated app version.
- Column resizing supports pointer interaction and keyboard arrow keys.
- Interactive controls have accessible labels and the record list is keyboard reachable.

### Chat and Agent Behavior

- Chat messages are held in renderer state and are not persisted.
- Chat requests are routed through the main process to a process-isolated local agent worker.
- The current local agent behavior is deterministic: it echoes receipt of the message, includes the selected record identifier when present, and includes `config/prompt.md` content when a local project prompt exists.
- Chat requests have timeout cleanup.
- Pending agent work is canceled when the app exits.

### Engineering Harness

- The deterministic harness commands are:
  - `npm run lint`
  - `npm run typecheck`
  - `npm run test:unit`
  - `npm run test:integration`
  - `npm run test:ui`
  - `npm run test:e2e`
  - `npm run smoke`
- CI runs lint, typecheck, unit, integration, UI, e2e, smoke, and harness audit checks.
- Smoke checks verify built Electron security settings and preload/main IPC channel pairing.
