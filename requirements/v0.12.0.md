## Product Goal

Add an evaluation layer on top of the v0.11.0 inference harness so completed inference runs can be scored, written back to Azure Blob Storage, and optionally published to an Experiment Catalog.

## Delta From v0.11.0

v0.11.0 created reproducible inference artifacts but explicitly did not score them. v0.12.0 documents the implemented evaluation behavior.

Newly in scope:

- A Python evaluation runner invoked by `npm run evaluation`.
- Discovery of latest or explicit inference run prefixes in Azure Blob Storage.
- Evaluation output artifacts written as `.eval.json` files beside inference artifacts.
- Retrieval, generation, output-structure, and timing metrics.
- GitHub Copilot SDK based fact judging for generation metrics.
- Optional metric publishing to the Experiment Catalog HTTP API.

Still out of scope:

- UI for browsing evaluation results.
- Human adjudication workflows for metric disagreements.
- Custom metric plug-ins.
- Evaluation storage outside the configured Azure inference container.
- Authentication or authorization for Experiment Catalog publishing beyond the configured endpoint.

## Functional Requirements

### Evaluation Runner

- The repository must expose `npm run evaluation` as the default evaluation command.
- `npm run evaluation` must run the Python evaluator with `--latest`.
- The evaluator must also support:
  - `--prefix <prefix>` to evaluate a specific blob prefix or run folder.
  - `--latest` to evaluate the newest run folder discovered from `*/manifest.json` blobs.
  - `--skip-existing` to skip evaluation outputs that already exist.
- `--latest` and `--prefix` must be mutually exclusive.
- Prefix normalization must trim leading and trailing slashes and append a trailing slash when a non-empty prefix is supplied.
- Latest-run discovery must sort numeric run folder names by numeric value and use the newest manifest folder.
- Evaluation must ignore inference `manifest.json` blobs and existing `.eval.json` blobs.

### Evaluation Configuration

- The evaluator must load default environment values from `ground-truth/config/.env` when the file exists.
- Existing process environment variables must take precedence over values loaded from `ground-truth/config/.env`.
- Quoted environment values in `ground-truth/config/.env` must be unquoted.
- `INFERENCE_CONTAINER` is required for evaluation.
- Evaluation storage must use the same Azure credential modes as inference output:
  - `AZURE_STORAGE_ACCOUNT_CONNSTRING`
  - `AZURE_STORAGE_ACCOUNT_NAME` with `DefaultAzureCredential`
- Evaluation must fail clearly when Azure dependencies or required Azure configuration are missing.

### Evaluation Input and Output Artifacts

- Evaluation input must be the v0.11.0 inference artifact shape containing `ground_truth` and `inference` objects.
- Each evaluated inference artifact must write a JSON evaluation artifact beside the source artifact.
- Evaluation output blob naming must replace a `.json` suffix with `.eval.json`; non-JSON source names must append `.eval.json`.
- Evaluation output blobs must use `application/json` content type when the Azure SDK supports content settings.
- Existing evaluation outputs must be replaced by default unless `--skip-existing` is set.
- Each evaluation result must include:
  - `source_blob`
  - `evaluated_at`
  - `status`
  - `source_status`
  - `paths`
  - `metrics`
  - optional `judge`
  - optional structured `error`
- If an evaluator exception occurs, the result status must be `failed` and the error must include message and type.
- The CLI must print a JSON summary with evaluated count, skipped count, failure count, failed artifact summaries, prefix, and Experiment Catalog publish counts.

### Evaluation Paths

- By default, generation metrics must read answers from `/answer`.
- By default, retrieval metrics must read evidence from `/evidence`.
- Ground truth records may override evaluation behavior with an `evaluation` object.
- Supported evaluation configuration keys are:
  - `answer_path`
  - `evidence_path`
  - `evidence_key`
  - `output_schema`
  - `ignored_output_structure_issues`
- `answer_path` and `evidence_path` must be JSON Pointers.
- JSON Pointers may include `*` wildcard path segments for per-turn evaluation over arrays.
- `evidence_key`, when present, must be a non-empty string.
- `output_schema`, when present, must be a JSON Schema object.
- If `evaluation.output_schema` is absent, the evaluator must use `ground_truth.schema` when available.
- `ignored_output_structure_issues` must be an array of objects with non-empty `path` and `keyword`, plus optional `message`.

### Retrieval Metrics

- Retrieval recall must be computed only when `evidence_key` is configured.
- When `evidence_key` is omitted, the evaluator must omit the `retrieval_recall` metric.
- Evidence identity must be derived from the configured evidence key, normalized as lowercase trimmed text.
- Expected evidence items missing the configured key must count as missing expected evidence.
- Actual evidence items missing the configured key must not create retrievable identities.
- Single-list retrieval recall must report:
  - `score`
  - `expected_evidence_count`
  - `actual_evidence_count`
  - `retrieved_relevant_count`
  - `missing_evidence`
- Multi-turn retrieval recall must report a `per_turn_macro_average` with per-turn metrics and aggregate counts.

### Generation Metrics

- Generation scoring must compare expected and actual answer text through a fact judge.
- The fact judge must extract comparable ground-truth facts and inference facts, then compare material equivalence.
- The judge output schema version must be `review-assistant.fact-judge.v1`.
- Judge comparison labels must be:
  - `equivalent`
  - `partial`
  - `missing`
  - `contradicted`
- Label scores must be:
  - `equivalent`: `1.0`
  - `partial`: `0.5`
  - `missing`: `0.0`
  - `contradicted`: `0.0`
- Generation metrics must include:
  - `generation_accuracy`
  - `generation_recall`
  - `generation_precision`
- Generation accuracy must expose supported and total fact counts plus per-fact support flags for both ground-truth and inference facts.
- Generation recall must measure supported ground-truth facts over all ground-truth facts.
- Generation precision must measure supported inference facts over all inference facts.
- Multi-turn generation scoring must use per-turn macro averages for accuracy, recall, and precision.
- Inference artifacts whose source status is not `completed` must not call the fact judge and must receive zero-valued generation metrics with a source-status method.

### GitHub Copilot Fact Judge

- The evaluator must create a Copilot SDK fact judge from environment configuration.
- `AGENT_MODEL` is required for the Copilot SDK fact judge.
- `REASONING_EFFORT`, when set, must be passed to the Copilot SDK session.
- `EVALUATION_JUDGE_TIMEOUT_SECONDS` must default to 120 seconds.
- The fact judge must support `COPILOT_GITHUB_TOKEN` when present.
- The judge session must:
  - stream responses.
  - disable custom instructions.
  - disable remote custom agents.
  - disable coauthoring, scheduling, MCP apps, canvas rendering, large output, and infinite sessions.
  - expose no tools to the judge.
  - use in-memory MCP OAuth token storage.
- The judge must parse raw JSON responses and JSON fenced-code responses.
- Evaluation output must include judge model metadata when a judge exposes a configured model.
- If observed Copilot response model metadata differs from the configured `AGENT_MODEL`, evaluation must fail rather than silently reporting metrics from an unexpected model.

### Output Structure Metric

- The evaluator must report `output_structure` for every artifact.
- `output_structure` must validate actual output against `evaluation.output_schema` or `ground_truth.schema`.
- If no schema is available, `output_structure` must fail with a schema issue.
- The output-structure validator must check:
  - object, array, string, number, integer, boolean, and null type constraints.
  - required object properties.
  - unexpected properties when `additionalProperties` is `false`.
  - array item schemas.
- Output-structure validation must not compare expected and actual answer values for semantic equality.
- Output-structure validation must not require arrays to have the same length as ground truth unless the schema itself requires it.
- Configured ignored issues must suppress only exact matching active issues by `path`, `keyword`, and optional `message`.
- The metric must report active issue count, active issues, validity, score, and ignored issue details when applicable.

### Timing Metrics

- Evaluation must derive timing metrics from each inference artifact.
- Timing metrics must include:
  - `meta_total_elapsed_ms`
  - `meta_assistant_request_elapsed_ms`
  - `meta_first_token_latency_ms`
  - `meta_stream_elapsed_ms`
  - `meta_tool_elapsed_ms`
  - `meta_unattributed_elapsed_ms`
- Timing values must be non-negative integers.
- Tool elapsed time must sum all transcript entries of type `tool-call`.
- Assistant timing must sum assistant-response transcript metadata values.
- Unattributed elapsed time must be total elapsed time minus assistant request elapsed time, floored at zero.

### Non-Completed Source Artifacts

- Source artifacts with inference status other than `completed` must still produce an evaluation output.
- Non-completed artifacts must preserve `source_status`.
- Non-completed artifacts must score generation accuracy, recall, and precision as zero.
- Non-completed artifacts must compute output structure from the available actual output, or `{}` when actual output is missing.
- Non-completed artifacts must compute timing metrics from the inference transcript.
- Non-completed evaluated artifacts must remain eligible for Experiment Catalog publishing when their evaluation status is `evaluated`.

### Experiment Catalog Publishing

- Experiment Catalog publishing must be optional.
- Publishing is enabled only when `EXPERIMENT_CATALOG_URL` is configured.
- When publishing is enabled, `EXPERIMENT_CATALOG_PROJECT` and `EXPERIMENT_CATALOG_EXPERIMENT` are required.
- The Experiment Catalog base URL must be absolute.
- The API base URL must normalize to a trailing `/api/` path.
- Before publishing results for a run folder, the evaluator must read existing result sets from:
  - `/api/projects/{project}/experiments/{experiment}/sets`
- The evaluator must publish each run folder to the next available suffixed set name:
  - `<run_folder>-A`
  - `<run_folder>-B`
  - `<run_folder>-C`
  - continuing through `Z`, `AA`, and beyond.
- Each published result payload must include:
  - `ref`
  - `set`
  - `inference_uri`
  - `evaluation_uri`
  - flattened numeric metrics
- Metrics that are objects must publish their numeric `score`.
- Numeric timing metrics must publish directly.
- Non-numeric metrics or scoreless metric objects must fail publishing clearly.
- Publishing must POST to:
  - `/api/projects/{project}/experiments/{experiment}/results`
- Experiment Catalog HTTP operations must use a 30-second timeout.
- Experiment Catalog HTTP operations must retry transient failures up to three attempts.
- HTTP 408, HTTP 429, HTTP 5xx, URL errors, and timeout errors must be retryable before final failure.
- HTTPS requests must use `certifi` CA roots when available unless `SSL_CERT_FILE` is already configured.

## Architecture Requirements

- The evaluation runner is a Python command-line tool under `eval/`.
- The Electron renderer must not own evaluation, Azure Blob access, fact judging, or catalog publishing behavior.
- Evaluation must read inference artifacts from Azure Blob Storage and write evaluation artifacts back to the same configured inference container.
- Fact judging must use the GitHub Copilot Python SDK, separate from the TypeScript inference runner.
- The TypeScript inference harness must continue to produce the transcript timing fields required by the evaluator.
- Python dependencies for evaluation must be declared in `eval/pyproject.toml`.

## Observability Requirements

- Evaluation progress must log source artifact names to stderr.
- Evaluation failures must log source artifact names, failure type when available, and failure reason to stderr.
- Evaluation CLI summary must be machine-readable JSON on stdout.
- Evaluation output must avoid logging or printing full secret values.
- Experiment Catalog publishing counts must be included in the CLI summary.

## Test and Harness Requirements

- Unit tests must cover:
  - Prefix normalization and latest-run selection.
  - Artifact filtering and evaluation output naming.
  - Environment loading and quoted values.
  - JSON Pointer resolution with wildcard support.
  - Retrieval recall with configured evidence keys.
  - Generation metrics from fact-judge output.
  - Fact-judge output validation failures.
  - Copilot SDK fact judge configuration and timeout defaults.
  - Output structure validation and ignored issue filtering.
  - Timing metric derivation.
  - Non-completed artifact scoring.
  - Experiment Catalog URL normalization, set suffix selection, publishing payloads, and retry behavior.
- The repository `npm run evaluation` command must remain aligned with the implemented Python evaluator entrypoint.
- The existing deterministic TypeScript gates remain unchanged for the application surface:
  - `npm run lint`
  - `npm run typecheck`
  - `npm run test:unit`
  - `npm run test:integration`
  - `npm run test:ui`
  - `npm run test:e2e`
  - `npm run smoke`
- Python evaluator tests must remain behavior-focused and exercise public evaluator functions and CLI behavior.

## Acceptance Criteria

v0.12.0 is complete when:

- Inference artifacts in Azure Blob Storage can be evaluated through `npm run evaluation`.
- The latest inference run can be discovered from manifests, and explicit prefixes can be evaluated on demand.
- Evaluation writes `.eval.json` artifacts beside source inference artifacts.
- Retrieval, generation, output-structure, and timing metrics are present and deterministic for the same inputs and judge output.
- Generation scoring uses a Copilot SDK fact judge with explicit model configuration and model mismatch protection.
- Timeout or failed inference artifacts still produce evaluation outputs with zero generation scores and timing metadata.
- Optional Experiment Catalog publishing creates suffixed run sets and posts flattened metrics with source and evaluation URIs.
- Evaluation failures are surfaced in structured evaluation output, stderr diagnostics, and the final CLI JSON summary.
