## Product Goal

Capture current application behavior that exists beyond the requirements documented through v0.7.0 so the requirements set remains a complete source of truth for implemented product behavior.

## Delta From v0.7.0

v0.7.0 unified project configuration, canonical mappings, and tool naming. v0.8.0 documents current behavior around record detail turn tabs, chat history continuation, configurable Copilot settings, URL rendering, and evidence-list presentation polish.

Newly in scope:

- Record detail tabs derived from the canonical `turns` mapping.
- Bounded chat history continuation across chat requests.
- App-level Copilot model and reasoning-effort settings.
- URL string rendering as links in record details and evidence cards.
- Evidence-list layout and disclosure behavior refinements.
- Prompt-size budgeting for chat history and attachment context.

Still out of scope:

- Persisting chat history across app restarts.
- User-editable agent settings in the UI.
- Deep-link preview panes or embedded URL content rendering.
- Multi-record comparison tabs.

## Functional Requirements

### Record Detail Turn Tabs

- When `config/config.json` explicitly maps one array path to the canonical `turns` mapping, the record detail view must render a tab list.
- The tab list must include an `Overview` tab plus one tab for each turn array item.
- Turn tabs must be labeled by zero-based array index, for example `Turn 0`, `Turn 1`, and `Turn 2`.
- Selecting a turn tab must render only that turn item's fields in the detail panel.
- Selecting `Overview` must render the normal record detail tree.
- While turn tabs are available, the mapped turns array in the overview must show its heading and item count but omit inline item rendering.
- The omitted turn array body must display exactly `(shown in tabs)`.
- The active tab must reset to `Overview` when the selected project or record changes, or when the previously active turn tab no longer exists.
- Turn tabs must not appear unless an explicit canonical `turns` mapping is configured.
- The tab list and active content panel must use accessible `tab`, `tablist`, and `tabpanel` semantics.

### Chat History Continuation

- Chat messages must remain visible in the chat panel across project changes during the same app session.
- The `Clear` action must remove current in-memory chat messages.
- Chat history must not be persisted across app restarts.
- Each new chat request must include prior user and assistant messages as bounded provider context.
- IPC validation must accept only user and assistant history messages.
- Chat history sent over IPC must be limited to at most 40 messages.
- Each chat history message must be non-empty and under 20,000 characters.
- Total IPC chat history content must be under 80,000 characters.
- Provider prompt assembly must include only recent eligible user and assistant messages.
- Provider prompt assembly must cap included history to the 20 most recent eligible messages, 40,000 total history characters, and 8,000 characters per history message.
- If a history message must be truncated for the provider prompt budget, truncation must be deterministic and must not change renderer-visible chat content.

### Agent Settings

- App-level environment configuration may include `AGENT_MODEL`.
- App-level environment configuration may include `REASONING_EFFORT`.
- `AGENT_MODEL` must be trimmed before use.
- Empty or whitespace-only `AGENT_MODEL` values must be ignored.
- Non-empty `AGENT_MODEL` values must be under 129 characters and must not contain whitespace or control characters.
- `REASONING_EFFORT` must be one of `low`, `medium`, `high`, or `xhigh`.
- Invalid agent settings must fail configuration loading with a clear configuration error.
- Parsed agent settings must be passed from main process orchestration to the isolated agent worker.
- The GitHub Copilot SDK session must receive configured `model` and `reasoningEffort` values when present.
- Agent availability status must include the active agent settings snapshot.
- Agent settings must be logged as configured setting keys only, not as arbitrary unredacted configuration payloads.

### URL Rendering

- String field values that are valid `http` or `https` URLs must render as links in generic record detail fields.
- URL links must open in a new browser window or tab.
- URL links must use `rel="noreferrer"`.
- Non-HTTP(S) strings must render as plain text.
- Invalid URL strings must render as plain text.
- Evidence-list fields must preserve the same URL link behavior as generic record detail fields.
- Evidence-list URL links must use evidence field text color so URI values remain visually consistent with surrounding evidence text.

### Evidence List Presentation

- An `evidence-list` array must render as an open disclosure group.
- Evidence-list item cards must be collapsed by default.
- Evidence-list groups must not expose an `Open in tab` action.
- Evidence item titles must prefer the object identifier selected by the generic object identifier rule.
- Evidence item summaries must show feedback rating summaries when submitted or pending ratings exist.
- Evidence fields with `editMode: "none"` must render in a compact wrapping read-only field group.
- Evidence fields with `editMode` other than `none` must render in an editable field group.
- Evidence fields must display read-only, logged, or inline editability indicators as appropriate.
- Evidence `content` fields must always occupy their own full-width row instead of sharing the compact wrapping row with smaller metadata fields.
- Logged evidence fields must hide their raw current value and show logged edit feedback controls and history instead.

### Prompt Context Budgeting

- Provider prompt assembly must enforce an overall prompt budget before sending content to GitHub Copilot.
- Attachment context included in the provider prompt must be capped independently from renderer-visible attachment metadata.
- Attachment content must be omitted with a clear marker when the prompt budget is exhausted.
- Individual attachment content included in the provider prompt may be truncated to fit the remaining budget.
- Prompt budgeting must not alter the selected files, renderer-visible attachment chips, or cached attachment lifecycle.

## Architecture Requirements

- Renderer remains responsible only for tab presentation, field display, and in-memory chat view state.
- Main process remains responsible for validating chat history and passing bounded history to agent orchestration.
- Agent worker remains responsible for provider prompt assembly, history budgeting, attachment budgeting, and Copilot SDK session settings.
- Agent settings must cross process boundaries through typed settings objects or validated serialized JSON, not through renderer-controlled input.
- URL rendering must remain display-only and must not grant renderer filesystem, storage, or tool access.

## Observability Requirements

- Chat start context logs must include chat history message count and total history character count.
- Agent provider spawn logs must include configured agent setting keys as `agentSettings`, or `none` when no settings are configured.
- Logs must continue to avoid full chat history, attachment content, record payloads, prompts, and secrets.

## Test and Harness Requirements

- UI tests must cover:
  - Turn-tab rendering from an explicit canonical `turns` mapping.
  - Absence of turn tabs when no turns mapping is configured.
  - Overview omission text exactly matching `(shown in tabs)`.
  - Chat history preservation across project changes and clearing through the `Clear` action.
  - Generic URL string fields rendering as links.
  - Evidence-list URI links, item disclosure behavior, editability indicators, and full-width content rows.
- Unit tests must cover:
  - Agent setting parsing and invalid setting failures.
  - Chat history IPC validation limits.
- Integration tests must cover:
  - Provider prompt history propagation for follow-up turns.
  - Configured agent settings crossing into the isolated provider worker.
- Existing deterministic gates remain:
  - `npm run lint`
  - `npm run typecheck`
  - `npm run test:unit`
  - `npm run test:integration`
  - `npm run test:ui`
  - `npm run test:e2e`
  - `npm run smoke`
  - `make audit-harness`

## Acceptance Criteria

v0.8.0 is complete when:

- Records with an explicit canonical `turns` mapping show overview and per-turn tabs while omitting duplicate inline turn details from the overview.
- Chat history continues within the app session, can be cleared by the user, and is bounded before crossing IPC and provider prompt boundaries.
- App-level Copilot model and reasoning-effort settings are validated, applied to SDK sessions, surfaced in status, and logged safely.
- Generic and evidence-specific URL values open in a new window or tab without losing evidence text styling.
- Evidence-list cards remain compact, accessible, collapsible, and readable, with large content fields on their own rows.
- Prompt assembly respects deterministic budgets for history and attachments.
